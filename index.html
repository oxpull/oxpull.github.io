FAQ

Project on GitHub
What is django-ox?

A database-backed worker for Django's Tasks framework. Tasks live in database rows. django-ox includes retries, worker recovery, recurring schedules, unique tasks, batches, rate limiting and workflows.

Do I need Redis or RabbitMQ?

No. django-ox uses your existing database. You still run a worker process to execute tasks.

What happens if a worker stops mid-task?

Its unfinished task returns to the queue and may run again. Make tasks tolerate repeated execution. External side effects aren't exactly-once.

Can I enqueue a task inside a database transaction?

Yes. Put the database write and enqueue() inside the same transaction.atomic() block. Both rows must use the same database. They commit or roll back together.

Are all features included?

Yes. All features are free and open source under BSD 3-Clause. Unique tasks, batches, rate limiting and workflows are included in django-ox 1.9.0. These four features require Django 6.0+. See the feature overview.

What should I install?

For a new installation, run pip install django-ox. Follow the getting started guide to configure Django and run a worker.

The oxpull 1.9.1 package on PyPI is a metapackage. It depends on django-ox>=1.9.1 and contains no Python module. django-ox supplies the oxpull module.

How do I upgrade an earlier oxpull install?

Follow the tested upgrade procedure. Stop workers and back up the database first. Uninstall the earlier oxpull distribution before installing django-ox 1.9.0.

Do not uninstall an earlier oxpull distribution after installing django-ox 1.9.0 unless you then repair the shared files as described below. This warning does not apply to the oxpull 1.9.0 metapackage: uninstalling it leaves django-ox's files in place.

If you already ran pip install -U oxpull, or installed django-ox over an earlier oxpull distribution, keep workers stopped while repairing the overlapping install. Run pip uninstall oxpull, then pip install --force-reinstall --no-deps django-ox, then pip check. Resolve any errors reported by pip check, then restart workers.
